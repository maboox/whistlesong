# معماری پیشنهادی (پیش‌نویس، هنوز تأیید نشده)

## خط لوله
1. **دیکود** فایل صوتی با Web Audio API.
2. **استخراج ملودی اصلی** (سخت‌ترین بخش):
   - آهنگ پلی‌فونیک است ولی سوت تک‌صداست.
   - گزینه‌ها: (الف) مدل نت‌نویسی مثل Basic Pitch (TF.js) در مرورگر؛ (ب) تک‌صدا‌یاب مثل pYIN/CREPE روی ملودی غالب؛ (ج) جداسازی منابع (vocals) با مدل ONNX قبل از pitch tracking.
3. **تحلیل ساختار**: تمپو/بیت، شروع و پایان نت‌ها، دینامیک (انرژی)، حدود رجیستر.
4. **نگاشت به محدوده‌ی سوت**: سوت انسان تقریباً ۵۰۰ تا ۴۰۰۰ هرتز؛ نت‌های خارج محدوده به اکتاو مناسب منتقل می‌شوند (بدون تغییر نام نت).
5. **سنتز سوت** (Web Audio / AudioWorklet یا رندر آفلاین):
   - موج تقریباً سینوسی + چند هارمونیک ضعیف.
   - نویز باند‌باریک (نفس) حول فرکانس پایه.
   - ویبراتو ملایم، glide بین نت‌ها، envelope حمله/رهایی طبیعی.
   - حجم صدا از انرژی آهنگ اصلی.
6. **خروجی**: پخش در مرورگر + دانلود WAV (و شاید MP3).

## استک پیشنهادی
- Vite + TypeScript، بدون فریمورک سنگین (یا React سبک).
- GitHub Actions: بیلد و دیپلوی به GitHub Pages.
- پردازش سنگین در Web Worker تا UI قفل نشود.

## ریسک‌ها
- کیفیت استخراج ملودی روی آهنگ‌های شلوغ.
- حجم مدل‌ها و زمان پردازش در مرورگر.
